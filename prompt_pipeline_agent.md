# Оркестратор OpenCode: каркас пайплайна Tenderplan

Этот файл — **общий каркас**. Конкретный сценарий **ровно одного тендера** описан в **`prompt_pipeline_agent_one.md`** (подключай его в чат, когда нужен один цикл).

Запускай в **[OpenCode](https://opencode.ai)** из корня **`C:\repos\YouDo\ai-agent-tenderplan`**.

**Не задавай пользователю уточняющих вопросов**, если в задаче уже указано число тендеров или приложены нужные промпты. Критерии анализа — **`prompt_tender_analyzer_new.md`**.

---

## Два запуска браузера (Chromium) — это норма, не ошибка

Автоматизация делится на **две независимые программы**, каждая **один раз** поднимает свой экземпляр Chromium на свой прогон:

| Запуск | Скрипт | Что делает в браузере |
|--------|--------|------------------------|
| **1** | `mian_parse_exactly_key.py` | Вход в приложение, список по ключу, открытие карточки(ек), скачивание вложений, метка парсера (**«На анализе»** / текст из `TENDER_DONE_MARK_TEXT` в настройках). |
| **2** | `mark_tender.py` | Вход по `auth.json`, карточка по `url` из JSON, **комментарий вердикта**, затем метка **«Подходит»** / **«Не подходит»**. |

**Между ними браузер закрыт.** Фазы анализа JSON и документов — **без Playwright** (только файлы и рассуждение модели).

### Чего агенту не делать

- **Не открывать** Tenderplan вручную «для проверки» посередине пайплайна и **не запускать** второй раз парсер, если цель — уже оставить комментарий и метку (это только **`mark_tender.py`**).
- **Не параллелить** два скрипта с браузером — сначала полностью заверши прогон **1**, потом анализ и JSON, потом прогон **2**.
- Если пользователь жалуется на «лишние окна» — уточни: должно быть **не более двух** запусков Chromium **на один завершённый цикл** «парсинг → анализ → метки»; три и больше подряд без причины — ошибка сценария агента.

## Терминал (PowerShell)

- **Не оборачивай** команды в `powershell -Command "..."` — ломается `$env:`.
- В `.env` только **`LOGIN`** и **`PASSWORD`**; ключ списка и прочее — **`runtime_settings.json`**.
- После `Set-Location` и `.\venv\Scripts\Activate.ps1` вызывай нужный скрипт (см. ниже).

## Режим A — один тендер

Выполняй **`prompt_pipeline_agent_one.md`** целиком (фазы 0–6): там **`--process 1`** и **`mark_tender.py --only-id "<TENDER_ID>"`**.

## Режим B — пакет из **K** тендеров (например 5)

Один прогон парсера может обработать **несколько** новых карточек в **одном** окне Chromium; затем один прогон **`mark_tender.py`** может проставить комментарии и метки **всем необработанным** строкам в JSON в **одном** втором окне.

### Что изменить относительно сценария «один тендер»

1. **Число K** возьми из запроса пользователя (например «5 тендеров» → **K = 5**). Если не указано — по умолчанию **1** и переходи на режим A.
2. **Фаза парсинга:** вместо `--process 1` выполни **`python .\mian_parse_exactly_key.py --process K`** (или `.\run_parse_n_tenders.ps1 -N K`). Скрипт **`run_parse_one_tender.ps1`** жёстко задаёт **1** — для пакета его не используй.
3. **Фаза 0:** зафиксируй множество каталогов **`downloads_recognize\`** до парсинга; после парсинга множество **`новые`** может содержать **до K** id (или меньше, если карточек не хватило).
4. **Фазы анализа:** для **каждого** `id` из **`новые`** (или из явного списка пользователя) выполни блок как в **`prompt_pipeline_agent_one.md`** фазы **3–4** (чтение файлов, вердикт, запись в accept/reject, удаление из `tenders_data.json`, очистка `downloads` / `downloads_recognize` для этого id). Порядок обработки id — **лексикографический**, если пользователь не задал другой.
5. **Фаза меток:** один запуск **`python .\mark_tender.py`** **без** **`--only-id`** — скрипт сам пройдёт все строки с **`is_marked`: false** в `tenders_accept.json` и `tenders_reject.json`. Если нужно ограничить только что добавленные id — можно вызвать **`mark_tender.py --only-id`** по очереди для каждого (тогда Chromium поднимется **K раз** на шаге меток — хуже; предпочитай один общий вызов без фильтра).

### Итого браузеров для пакета в «правильном» сценарии

- **1×** Chromium — парсинг K карточек (`--process K`).
- **1×** Chromium — все комментарии и метки для накопленной очереди (`mark_tender.py` без `--only-id`).

## Обрывы и повторы

- Парсинг прошёл, анализ нет — **не удаляй** `downloads` / `downloads_recognize`; продолжи анализ с сохранённых данных.
- JSON записан, **`mark_tender`** упал — повтори **`python .\mark_tender.py`** или **`--only-id`** для проблемного id.
