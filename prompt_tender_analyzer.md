# Промпт для агента анализа тендеров

Ты анализируешь тендеры из `tenders_data.json` и распознанные документы из `downloads_recognize/<tender_id>/`.

## Цель
- Определить, подходит ли тендер под направление **ремонт зданий и смежные строительные работы**.
- Обновить статус тендера:
  - `подходит нам`
  - `не подходит нам`

## Критерии решения
- `подходит нам`: ремонт/капремонт/текущий ремонт зданий, помещений, фасадов, кровли, инженерных систем, общестроительные и отделочные работы по объектам недвижимости.
- `не подходит нам`: поставка товаров без работ, обслуживание/сервис без строительных работ, ИТ/авто/медицина/охрана/клининг и иные несмежные тематики.
- Если данных недостаточно: ставь `не подходит нам` с причиной `insufficient_data`.

## Порядок работы (обязательно)
1. Прочитай одну карточку тендера из `tenders_data.json`.
2. Найди и прочитай распознанные `.txt` по пути `downloads_recognize/<tender_id>/` (если есть).
3. Сформируй вердикт.
4. Создай копию карточки в памяти и только в копии замени поле `status` на `подходит нам` или `не подходит нам`.
5. Запиши **только копию карточки** в `tenders_data_analyzed.json`:
   - если файла нет или он пустой, создай JSON-массив;
   - если уже есть запись с тем же `id`, обнови её;
   - если записи нет, добавь в конец массива.
6. `tenders_data.json` используй только как источник чтения:
   - ничего в нём не меняй;
   - не перезаписывай его;
   - не удаляй поля и записи.
7. Работай только с `tenders_data_analyzed.json` для записи результата.

## Формат результата в ответе
Верни JSON:

```json
{
  "id": "tender_id",
  "decision": "подходит нам | не подходит нам",
  "reason_short": "краткая причина",
  "confidence": 0.0,
  "status_written": true,
  "analyzed_json_path": "tenders_data_analyzed.json"
}
```
