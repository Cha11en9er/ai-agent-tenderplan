# Автоматизация отбора тендеров на Tenderplan

Ручной просмотр тендеров на [tenderplan.ru](https://tenderplan.ru) занимает много времени. Этот репозиторий автоматизирует сбор карточек, скачивание вложений, распознавание текста и подготовку данных для решения ИИ-агента; финальное решение по участию по-прежнему принимает человек на сайте.

## Общая схема пайплайна

1. **Парсер (Playwright)** — вход в аккаунт, переход к нужному «ключу» в боковой панели, обход **неотмеченных** карточек в списке, сохранение данных в JSON, скачивание файлов, **моментальное распознавание** в текстовые `.txt`.
2. **ИИ-анализ (например, OpenCode в этой папке)** — по промпту читаются `tenders_data.json` и `downloads_recognize/`, вердикты записываются в `tenders_accept.json` и `tenders_reject.json`, карточки убираются из очереди в `tenders_data.json` (см. правила в промпте).
3. **Проставление меток на сайте** — скрипт `mark_tender.py` выставляет на Tenderplan пункты списка меток **«Подходит»** / **«Не подходит»** (как в UI), чтобы дальше удобно отфильтровать и просмотреть вручную. Записи берутся из `tenders_accept.json` и `tenders_reject.json`.

Окружение в инструкции ниже: **Windows**, оболочка **PowerShell**.

## Подготовка окружения (один раз)

Перейдите в каталог проекта:

```powershell
Set-Location "C:\repos\YouDo\ai-agent-tenderplan"
```

Создайте и активируйте виртуальное окружение (если ещё не создано):

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Установите зависимости Python (минимум для парсера и разметки нужны `playwright`, `python-dotenv`; для распознавания — пакеты из `requirements_recognize.txt`):

```powershell
pip install playwright python-dotenv
pip install -r requirements_recognize.txt
python -m playwright install chromium
```

> Для OCR в распознавании может понадобиться установленный **Tesseract** и настройки под Windows — см. модуль `recognize_files`.

## Конфигурация: секреты и «операционные» настройки

### Файл `.env` (только вход на сайт)

Подхватывается через `python-dotenv` (`load_dotenv()` в скриптах). В репозитории есть шаблон **`.env.example`**.

| Переменная | Назначение |
|------------|------------|
| `LOGIN` | Логин Tenderplan |
| `PASSWORD` | Пароль |

Не коммитьте свой `.env` в git (он в `.gitignore`).

### Файл `runtime_settings.json` (правится агентом и вручную)

Все **не секретные** параметры пайплайна удобнее держать здесь — ИИ-агент может менять их по промпту без правки `.env`. Читает модуль **`runtime_config.py`**.

| Поле JSON | Назначение |
|-----------|------------|
| `TENDER_KEY_TEXT` | Название ключа в боковой панели Tenderplan |
| `TARGET_KEY_TEXT` | Запасное имя ключа, если основное пустое |
| `TENDERS_TO_PROCESS` | Сколько неотмеченных тендеров за запуск парсера (по умолчанию в коде `3`, если ни JSON, ни env не заданы) |
| `TENDER_DONE_MARK_TEXT` | Метка на сайте после сбора карточки парсером |
| `LIST_PLATE_ROW_PX` | Шаг прокрутки виртуализированного списка карточек (пиксели) |
| `RECOGNIZE_MAX_ZIP_DEPTH` | Глубина вложенных ZIP при распознавании |

**Приоритет:** значение из **`runtime_settings.json`**, иначе переменная окружения с тем же именем, иначе встроенное значение по умолчанию. Флаг парсера **`--process N`** по-прежнему перекрывает лимит тендеров на один запуск.

Шаблон без ваших данных: **`runtime_settings.example.json`** (скопируйте в `runtime_settings.json` при первом клонировании).

## Файлы авторизации

| Файл | Назначение |
|------|------------|
| `auth.json` | Снимок сессии Playwright (`storage_state`): куки и связанное состояние. Если файл есть, парсер и `mark_tender.py` стартуют уже авторизованными. |
| `save_auth.py` | Отдельный сценарий: открывает браузер (не headless), вызывает `login()` из `tenderplan_login.py`, сохраняет `auth.json`. Удобно для первичной или ручной переавторизации. |
| `tenderplan_login.py` | Общая функция `login(page)`: переход на сайт, «Войти», заполнение `LOGIN`/`PASSWORD` из `.env`. |

Если `auth.json` отсутствует, `mian_parse_exactly_key.py` при необходимости сам выполнит логин и сохранит сессию.

## Этап 1: основной парсер и распознавание

**Главный скрипт:** `mian_parse_exactly_key.py` (имя файла с опечаткой «mian», но запускать нужно как есть).

Что делает скрипт в типичном прогоне:

- Загружает `.env`, поднимает Chromium через Playwright (**окно браузера видно**, `headless=False`).
- Открывает `https://tenderplan.ru/app`, восстанавливает сессию из `auth.json` или логинится через `tenderplan_login.login`.
- Находит в сайдбаре ключ с текстом из `TENDER_KEY_TEXT` / `TARGET_KEY_TEXT` и переходит к списку тендеров.
- Ищет карточки **без** индикатора метки в UI; для уже обработанных в JSON с `status == "анализируем"` повторно не заходит (см. `collect_analyzed_ids` в коде).
- По каждому выбранному тендеру: собирает поля карточки, скачивает вложения в `downloads\<tender_id>\`, сохраняет HTML карточки в `tenders_dom\<tender_id>.html`, ставит на сайте метку `TENDER_DONE_MARK_TEXT`.
- Дописывает/мерджит массив в **`tenders_data.json`**.
- После закрытия браузера запускает **`recognize_files.recognize_tender_downloads`**: результаты складываются в **`downloads_recognize\<tender_id>\`** (вложенная структура, текстовые `.txt`).
- Дополнительно может сохраняться дамп DOM главной страницы в `main_page_dom.html`.

**Запуск (PowerShell, из корня репозитория, с активированным venv):**

```powershell
Set-Location "C:\repos\YouDo\ai-agent-tenderplan"
.\venv\Scripts\Activate.ps1
python .\mian_parse_exactly_key.py
```

Ровно один тендер независимо от `.env`: `python .\mian_parse_exactly_key.py --process 1` (так же делает **`run_parse_one_tender.ps1`**).

**Опционально — только сохранить авторизацию вручную:**

```powershell
.\venv\Scripts\Activate.ps1
python .\save_auth.py
```

## Автоматизация одного тендера (агент-оркестратор)

Чтобы один запуск агента вёл цепочку **парсинг → анализ → JSON → очистка папок → метка на сайте**, используй **`prompt_pipeline_agent_one.md`** (ориентир под **OpenCode** и любой агент с терминалом из корня проекта).

Вспомогательно:

- **`run_parse_one_tender.ps1`** — запускает парсер с **`--process 1`** (лимит не берётся из `.env`, если там другое число).
- **`python mark_tender.py --only-id "<id>"`** — метка только для указанного тендера (остальные необработанные в JSON не трогает).

Полностью «одним скриптом без LLM» шаг анализа не заменить без отдельного API — см. **`prompt_pipeline_agent_one.md`**.

## Этап 2: анализ ИИ-агентом (OpenCode и промпт)

После того как в `tenders_data.json` появились новые карточки и в `downloads_recognize\` — распознанный текст:

1. Запускаете **OpenCode** в каталоге проекта `C:\repos\YouDo\ai-agent-tenderplan`.
2. Даёте агенту промпт из файла **`prompt_tender_analyzer.md`**.

Промпт задаёт:

- какие пути читать (`tenders_data.json`, `downloads_recognize\<id>\**\*.txt`);
- куда писать **`tenders_accept.json`** и **`tenders_reject.json`**;
- как обновлять статусы и удалять обработанные записи из **`tenders_data.json`**;
- формат полей (`reason_short`, `decision`, `confidence`, `is_marked: false` до вызова разметчика и т.д.).

Итог этапа: два JSON-файла с вердиктами и актуализированная очередь в `tenders_data.json`.

## Этап 3: проставление меток на сайте

**Скрипт:** `mark_tender.py`.

- Читает **`tenders_accept.json`** и **`tenders_reject.json`** (ожидается JSON-массив объектов).
- Берёт записи, у которых **`is_marked`** не истина (ещё не отмечены скриптом).
- Для каждой открывает `url` тендера на сайте и в интерфейсе выбирает метку:
  - из accept — на сайте выбирается метка **«Подходит»**;
  - из reject — **«Не подходит»**.
- После успеха выставляет в объекте **`is_marked`: `true`** и перезаписывает JSON (прогресс не теряется при сбоях посередине).

**Запуск:**

```powershell
Set-Location "C:\repos\YouDo\ai-agent-tenderplan"
.\venv\Scripts\Activate.ps1
python .\mark_tender.py
```

Только один `id` из очереди меток:

```powershell
python .\mark_tender.py --only-id "69f47e2d735a1aaca4a6be3c"
```

Дальше вы вручную просматриваете отмеченные тендеры на Tenderplan и принимаете решение об участии.
